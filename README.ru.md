# php2shell.sh — закрываем PHP2Shell (CVE-2026-109618, CVE-2026-109619) на Debian/Ubuntu с PHP от Surý

[English version](README.md)

`php2shell.sh` проверяет и обновляет **все установленные версии PHP** на сервере Debian/Ubuntu, закрывая PHP2Shell — две критические уязвимости удалённого выполнения кода без авторизации в ядре PHP (CVE-2026-109618, CVE-2026-109619, CVSS v4.0 9.2, исправления вышли 21 октября 2026 года).

Скрипт написан для Debian/Ubuntu с PHP от Surý (репозиторий Ondřej Surý), где на одной машине часто стоит от 2 до 12 версий PHP, и учитывает случаи, когда «успешный» `apt upgrade` оставляет сервер уязвимым. На серверах с панелью [HestiaCP](https://hestiacp.com/) он дополнительно проверяет собственный PHP панели (`hestia-php`) и снимает ответы всех сайтов до и после патча.

Версия **1.0** (23.10.2026). Проверен в работе на 6 серверах Ubuntu с HestiaCP: пропатчено 50 установок PHP из 50, около 140 сайтов проверены до и после — ответы не изменились, простой 1–2 секунды на перезапуск php-fpm.

## Почему не просто `apt upgrade`

| Подводный камень | Что происходит | Что делает скрипт |
|---|---|---|
| Переименование PPA ondrej | На старых серверах apt с 2022 года молча не обновляет индекс PHP из-за смены поля `Label`. `apt upgrade` пишет «уже новейшая версия», хотя пакетам несколько лет | Обновляет индекс репозитория и останавливается, если индекс PHP не обновился, — вместо ложного «успеха». Ручное решение: `apt-get update --allow-releaseinfo-change-label` |
| Номер версии ничего не доказывает | У веток 5.6–8.1 версия PHP не меняется, меняется только ревизия пакета (7.4.33-30 → 7.4.33-31) | Ищет CVE в changelog пакета `phpX.Y-common` |
| Много версий PHP на сервере | Забытая 5.6 с одним сайтом открывает весь сервер | Обновляет все установленные `php*` разом |
| Без перезапуска патч не работает | Запущенные php-fpm держат старый код в памяти | Перезапускает каждый `phpX.Y-fpm`, Apache и панель |
| У панели свой PHP | HestiaCP использует отдельный пакет `hestia-php` | Проверяет и обновляет его отдельно |
| Ошибки репозитория не останавливают apt | При ошибке подписи apt берёт старый индекс и «успешно» ничего не делает | Останавливается до установки, если индекс репозитория PHP не обновился |

## Требования

- Debian 11/12/13 или Ubuntu 20.04/22.04/24.04/26.04, root или sudo.
- PHP из репозитория Ondřej Surý (`deb.sury.org` / `ppa:ondrej/php`).
- Не меньше 1 ГБ свободного места в `/var`.

**Не подходит** для CentOS/RHEL/AlmaLinux, cPanel, Plesk, BitrixVM. Для CentOS 7 исправленной сборки PHP нет ни у кого — нужен переезд, своя сборка PHP или коммерческая расширенная поддержка.

## Использование

Скачайте `php2shell-kit.tar.gz` в разделе [Releases](../../releases), загрузите на сервер и выполните:

```bash
tar xzf php2shell-kit.tar.gz && cd php2shell-kit
sudo ./php2shell.sh check          # проверка, ничего не меняет
sudo ./php2shell.sh patch          # патч, спросит подтверждение
sudo ./php2shell.sh patch --yes    # без вопроса, для автоматизации
sudo ./php2shell.sh sites          # только снимок ответов сайтов HestiaCP
```

Рекомендуемый порядок: `check` → `patch` на одном сервере → проверка сайтов → остальные серверы → снова `check`.

### Режимы

| Режим | Что делает |
|---|---|
| `check` | Для каждой версии PHP ищет исправление CVE в changelog `phpX.Y-common`, показывает версию `hestia-php` |
| `patch` | Снимок сайтов → `apt-get update` → обновление только установленных `php*` и `hestia-php` → перезапуск php-fpm, apache, панели → проверка и сравнение сайтов |
| `sites` | Снимок HTTP-кодов всех сайтов HestiaCP |

### Коды выхода

| Код | Что значит |
|---|---|
| `0` | всё пропатчено |
| `1` | остались уязвимые версии |
| `2` | ошибка или остановка |

### Пример вывода (`check` после патча)

```text

  hestia-php 8.5.12-1+ubuntu22.04                        PHP 8.5.12 (cli)

```

## Защита от ошибок

- Ставит новые версии только уже установленных пакетов, конфиги PHP не перезаписывает.
- Если репозиторий PHP не обновился — останавливается до установки.
- Не запускается дважды одновременно, проверяет место на диске.
- Всё пишет в `/var/log/php2shell/`: общий лог, лог apt, снимки сайтов до и после.

## FAQ

**Сайты упадут?** Нет. Обновление идёт 15–30 минут на фоне, пауза — 1–2 секунды на перезапуск php-fpm.

**После патча осталось «УЯЗВИМ»?** Для этой версии нет сборки под вашу ОС или архитектуру: переведите сайты на 8.2+ и удалите её.

**«Репозиторий PHP не обновился»?** Обычно истёк ключ или нет сети; смотрите строки `E:` в выводе.

**«Сайты: ЕСТЬ ИЗМЕНЕНИЯ»?** Проверьте перечисленные домены вручную; сайт, отдававший 500 до патча, отдаст 500 и после.

**Как откатить?** Не нужно: обновление в пределах той же версии PHP (8.2.33 → 8.2.35).

**После патча** проверьте сервер на следы атаки с 17 октября 2026 года: падения воркеров PHP, веб-шеллы, новые задания cron и SSH-ключи.
